# UI Redesign v1.0 + Stop Generation

## Complexity: ✅ Simple — UI layout + component reskin + one AbortController addition

## Context
The original UI had a dark tab-based sidebar that looked rough and upload functionality buried in the chat input. This plan redesigns the UI to match a clean reference design and adds a stop-generation button for better UX.

---

## Changes Made

### 1. `src/App.tsx`
Added `activePage: 'chat' | 'documents'` state. Passes `activePage`, `onNavigate`, and `userEmail` down to `ChatPage`.

### 2. `src/components/ThreadList.tsx` → Full Sidebar
Redesigned from a dark thread-only list into a full application sidebar:
- **Top**: Brand name "RAG Chat"
- **Nav**: Chat + Documents items with active highlight (light gray background)
- **Thread list**: visible only when on Chat page, with inline rename/delete on hover
- **Bottom**: initials avatar (from email) + email + sign out button
- Switched from dark (`bg-gray-900`) to light (`bg-white border-r`) theme

### 3. `src/pages/DocumentsPage.tsx` — Drag-and-Drop Redesign
- Removed old card-based layout with top-right upload button
- Added drag-and-drop zone: `onDragOver` + `onDrop` + `onDragLeave` + hidden file input
- Document list rows: file icon | filename | status badge | size · chunks | Delete button
- Status badges: green=completed, red=error, gray=processing (animated pulse)
- Uses existing `useDocuments` hook — no hook changes needed

### 4. `src/pages/ChatPage.tsx`
- Removed `useDocuments`, upload state, upload handlers, and upload props from `MessageInput`
- Added `activePage`, `onNavigate`, `userEmail` props
- Renders `<DocumentsPage />` when `activePage === 'documents'`
- Passes `streaming` and `onStop` to `MessageInput`

### 5. `src/components/MessageInput.tsx`
- Removed: paperclip button, file input ref, upload chip, upload progress bar, all upload-related props
- Simplified props: `{ onSend, disabled, streaming, onStop }`
- Added **Stop button**: shows when `streaming === true`, replaces Send button
  - Filled square SVG icon (stop icon)
  - Calls `onStop()` on click

### 6. `src/hooks/useChat.ts` — AbortController
- Added `abortRef = useRef<AbortController | null>(null)`
- Added `stopStreaming` callback: calls `abortRef.current?.abort()`
- In `sendMessage`: creates a new `AbortController` per request, stores in `abortRef`
- Passes `controller.signal` to `sendMessageStream`
- Catch block: silently handles `AbortError`, cleans up streaming state

### 7. `src/lib/api.ts` — AbortSignal
- Added `signal?: AbortSignal` parameter to `sendMessageStream`
- Passes signal to `fetch()` call
- AbortError propagates naturally to `useChat` catch block

## Stop Generation Flow
1. User sends message → `sendMessage` creates `AbortController`, stores in `abortRef`
2. While streaming → Send button replaced by Stop button (square icon)
3. User clicks Stop → `stopStreaming()` → `controller.abort()`
4. `fetch()` or `reader.read()` throws `AbortError`
5. `useChat` catch block: `e.name === 'AbortError'` → silently clean up → `setStreaming(false)`, `setStreamingContent("")`
6. UI returns to normal idle state, partial response discarded
