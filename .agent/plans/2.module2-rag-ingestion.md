# Module 2: BYO Retrieval + Memory (RAG Pipeline)

**Complexity: ⚠️ Medium** — Multiple coordinated systems but each phase is independently testable.

## Context

Module 1 built the chat shell. Module 2 adds the actual RAG capability: users upload PDFs, the backend parses/chunks/embeds them into pgvector, and the chat automatically retrieves relevant chunks to ground the LLM's answers. This is the core feature of the masterclass.

**Embeddings:** Hugging Face Inference API (free) — model `sentence-transformers/all-MiniLM-L6-v2`, 384 dimensions.
**LLM:** Groq `llama-3.1-8b-instant` (unchanged).

---

## Pre-requisites (before running)

1. Sign up at huggingface.co → Settings → Access Tokens → create a token
2. Add `HUGGINGFACE_API_KEY=hf_...` to `backend/.env`
3. Enable Supabase Realtime on the `documents` table:
   Run in SQL Editor: `alter publication supabase_realtime add table documents;`

### 2.2 Update `backend/app/config.py`

Add to `backend/.env.example`:
```
HUGGINGFACE_API_KEY="hf_...your_token"
```

### 2.3 Add to `backend/app/models.py`
```python
class DocumentResponse(BaseModel):
    id: str
    user_id: str
    filename: str
    storage_path: str
    size_bytes: int | None
    status: str
    error_msg: str | None
    chunk_count: int
    created_at: datetime
    updated_at: datetime
```

### 2.4 New file: `backend/app/services/embedding_service.py`
- `chunk_text(text) -> list[str]` — 500-char chunks, 50-char overlap
- `get_embeddings(texts) -> list[list[float]]` — batch HF API calls (32 per request), `wait_for_model: True`, 60s timeout
- `get_query_embedding(text) -> list[float]` — single text wrapper

HF endpoint: `https://api-inference.huggingface.co/pipeline/feature-extraction/sentence-transformers/all-MiniLM-L6-v2`

### 2.5 New file: `backend/app/services/ingestion_service.py`
- `_broadcast_status(document_id, status, error_msg)` — writes to `documents` table (triggers Realtime)
- `ingest_document(document_id, user_id, file_bytes, filename)` — async pipeline:
  1. `parsing` → extract text with `pypdf.PdfReader`
  2. `chunking` → `chunk_text()`
  3. `embedding` → `get_embeddings()`
  4. Insert chunk rows in batches of 100
  5. Update status to `complete` with `chunk_count`
  6. On any exception → status `error` with message

### 2.6 New file: `backend/app/routers/documents.py`
- `POST /documents` — receives `UploadFile`, validates PDF + 50MB limit, uploads to Supabase Storage at `{user_id}/{filename}`, inserts document row (status=`uploading`), fires `asyncio.create_task(ingest_document(...))`, returns 201 immediately
- `GET /documents` — list user's documents ordered by `created_at desc`
- `DELETE /documents/{id}` — delete storage file + document row (chunks cascade)

### 2.7 Update `backend/app/main.py`
- Import and register `documents` router
- Add `http://localhost:5174` to `allow_origins`

**Validate:** Restart backend. Upload a PDF via Postman/curl. After ~30s, document status = `complete` in Supabase Table Editor with `chunk_count > 0`.

## Phase 3: Backend — Retrieval

### 3.1 New file: `backend/app/services/retrieval_service.py`
- `retrieve_context(user_id, query) -> list[dict]` — checks if user has any chunks, embeds query, calls `match_chunks` RPC (TOP_K=5, threshold=0.3)
- `build_context_block(chunks) -> str` — formats chunks as `--- RELEVANT DOCUMENT CONTEXT ---` block

### 3.2 Modify `backend/app/services/chat_service.py`
- Import `retrieve_context`, `build_context_block`
- Update `build_system_prompt(context_block="")` to append context block when present with instruction: "Use the following document context to answer. If not in context, say so and use general knowledge."
- In `stream_chat()`: call `retrieve_context(user_id, user_message)` before assembling messages, inject context into system prompt
- Before token streaming, if chunks found: `yield f"data: __sources:{len(chunks)}\n\n"`

**Validate:** Upload a PDF, ask a question about it in chat. LangSmith trace should show context block in system prompt.
