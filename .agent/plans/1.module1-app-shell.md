# Module 1: App Shell + Observability

⚠️ **Medium** — Multiple systems to wire together (FastAPI, React, Supabase, Groq, LangSmith), but each piece is well-understood.

## Context
Starting from a completely empty repo. Module 1 establishes the full-stack foundation: auth, chat UI, stateless message history, Groq LLM streaming, and LangSmith observability. The stateless pattern (fetch history from DB, send it all with each request) is intentional — it's the same pattern used in all subsequent modules.

## Phase 1: Database (Supabase SQL Editor)

Run the following SQL in your Supabase project:

### 1.1 — Create `threads` table + RLS
```sql
create table threads (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  title text not null default 'New Chat',
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create or replace function update_updated_at()
returns trigger as $$
begin new.updated_at = now(); return new; end;
$$ language plpgsql;

create trigger threads_updated_at
  before update on threads
  for each row execute function update_updated_at();

alter table threads enable row level security;
create policy "Users see own threads"    on threads for select using (auth.uid() = user_id);
create policy "Users insert own threads" on threads for insert with check (auth.uid() = user_id);
create policy "Users update own threads" on threads for update using (auth.uid() = user_id);
create policy "Users delete own threads" on threads for delete using (auth.uid() = user_id);
```

### 1.2 — Create `messages` table + RLS
```sql
create table messages (
  id uuid primary key default gen_random_uuid(),
  thread_id uuid not null references threads(id) on delete cascade,
  user_id uuid not null references auth.users(id) on delete cascade,
  role text not null check (role in ('user', 'assistant', 'system')),
  content text not null,
  created_at timestamptz not null default now()
);

alter table messages enable row level security;
create policy "Users see own messages"    on messages for select using (auth.uid() = user_id);
create policy "Users insert own messages" on messages for insert with check (auth.uid() = user_id);
```

**Validation:** Tables visible in Supabase Table Editor. Querying with anon key returns no rows (RLS working).

### 2.2 — `app/config.py`
Use `pydantic-settings` `BaseSettings` to load all env vars. Fails at startup if any are missing.

### 2.3 — `app/main.py`
FastAPI app with CORS middleware (allow `http://localhost:5173`), `/health` endpoint, include both routers.

### 2.4 — `app/database.py`
Supabase service role client singleton. Backend uses service role (bypasses RLS) but enforces ownership by reading `user_id` from the validated JWT.

### 2.5 — `app/auth.py`
JWT validation via `GET {SUPABASE_URL}/auth/v1/user` using `httpx`. Requires both `Authorization: Bearer <token>` and `apikey: <service_role_key>` headers (Supabase requires both). Returns user dict; routes read `user["id"]`.

### 2.6 — `app/models.py`
Pydantic models: `ThreadCreate`, `ThreadResponse`, `MessageCreate`, `MessageResponse`.

### 2.7 — `app/routers/threads.py`
- `POST /threads` — insert row, return `ThreadResponse`
- `GET /threads` — list by `user_id`, ordered by `updated_at DESC`

### 2.8 — `app/services/tracing.py`
Set `LANGCHAIN_TRACING_V2=true`, `LANGCHAIN_API_KEY`, `LANGCHAIN_PROJECT` in `os.environ` **before** importing langsmith. Return a `wrap_openai(AsyncOpenAI(...))` client pointed at Groq:
```python
base_url="https://api.groq.com/openai/v1"
api_key=settings.groq_api_key
```

### 2.9 — `app/services/chat_service.py` ⭐ Core logic
Async generator that:
1. Fetches full message history from DB (ordered `created_at ASC`)
2. Assembles `[system, ...history, user_message]` — **stateless pattern**
3. Saves user message to DB
4. Streams from Groq (`model="llama-3.3-70b-versatile"`, `stream=True`)
5. Yields `data: <token>\n\n` SSE chunks
6. After stream ends, saves complete assistant message to DB
7. Yields `data: [DONE]\n\n`

**Gotcha:** Don't pass `stream_options` to Groq — unsupported, will error.

### 2.10 — `app/routers/messages.py`
- `POST /threads/{thread_id}/messages` → `StreamingResponse(chat_service_generator, media_type="text/event-stream")` with headers `Cache-Control: no-cache` and `X-Accel-Buffering: no`
- `GET /threads/{thread_id}/messages` → list messages for thread

**Validation:** `uvicorn app.main:app --reload` starts. `curl /health` → `{"status":"ok"}`. POST to messages returns `text/event-stream`.

### 3.4 — `src/lib/api.ts` ⭐ SSE streaming
All backend calls. Attaches `Authorization: Bearer <session.access_token>` to every request.

**Critical:** Use Fetch API + manual `ReadableStream` reader for SSE — **not** `EventSource`. `EventSource` doesn't support POST or custom auth headers.

```typescript
// SSE stream reading pattern
const reader = res.body!.getReader()
const decoder = new TextDecoder()
while (true) {
  const { done, value } = await reader.read()
  if (done) break
  for (const line of decoder.decode(value).split('\n')) {
    if (line.startsWith('data: ')) {
      const payload = line.slice(6)
      if (payload === '[DONE]') { onDone(); return }
      onChunk(payload)
    }
  }
}
```

### 3.5 — Auth: `useAuth.ts` + `LoginPage.tsx`
`useAuth`: `supabase.auth.getSession()` on mount + `onAuthStateChange` listener. Returns `{ user, loading }`.

`LoginPage`: Email + password form. "Sign In" / "Sign Up" buttons. Inline error display. Calls `supabase.auth.signInWithPassword` or `supabase.auth.signUp`.

### 3.6 — `App.tsx`
Simple conditional: `loading ? spinner : user ? <ChatPage /> : <LoginPage />`. No React Router needed for Module 1.

### 3.7 — `useThreads.ts` + `ThreadList.tsx`
Hook manages thread list + active thread ID. `ThreadList` renders sidebar with "New Chat" button and clickable thread items.

### 3.8 — `useChat.ts` + `ChatWindow.tsx` + `MessageInput.tsx`
`useChat`: Loads messages when `threadId` changes. `sendMessage` creates thread if none active, then streams response using `api.sendMessageStream`, accumulating `streamingContent` token by token. After `[DONE]`, reloads messages from DB to get proper IDs.

`ChatWindow`: User messages right-aligned, assistant left-aligned. Shows live streaming bubble while `streaming=true`. Auto-scrolls to bottom.

`MessageInput`: Textarea + Send button. Disabled while streaming. Enter to send (Shift+Enter for newline).

### 3.9 — `ChatPage.tsx`
Full layout: `flex h-screen` with 256px sidebar (`ThreadList`) + flex-1 column (`ChatWindow` + `MessageInput`).

**Validation:** `npm run dev` starts at `localhost:5173`.
